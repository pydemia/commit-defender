# Automatic reviews

Run **Commit Defender: Automatic Reviews** and choose a repository/worktree to toggle Save, Stage, Commit or Push independently. The choice is stored in extension user state. User Settings provide the defaults; `.vscode/settings.json` cannot enable automatic execution. All four triggers default to off, and manual review commands remain available.

Save reviews the saved working-tree files against HEAD. Typing alone does not trigger a review. Stage reviews the current staged changes after the index content changes, preserving partial staging even when the editor contains later edits. Linked worktrees use their actual index path, and workspace roots are tracked separately.

Events wait three seconds to combine repeated changes. Ready events enter the independent service’s serial review queue. Save defaults to a ten-minute minimum interval; automatic admission defaults to six review starts per hour for the same profile/worktree. Change `automaticSaveIntervalSeconds` or `automaticReviewsPerHour` in User Settings. These limits count review starts, not provider API calls or tokens. Manual reviews remain available when automatic work is deferred. A manual review waiting for or executing in the common broker takes priority over new automatic model starts in the same profile/worktree. Already admitted reviews continue, and the service resumes its saved queue after manual priority is released.

Auto Save and external file changes are excluded by default. Enable **Include Auto Save** or **Include external file changes** separately when needed. **Pause automatic reviews in this worktree** suspends that worktree; **Pause all automatic reviews** sets the global pause. Clear `commitDefender.automaticReviewsPaused` in User Settings to resume globally. A worktree selection cannot override the global pause.

Newer input cancels obsolete automatic work. Results update diagnostics, inline comments and review history without opening a summary or changing editor focus. Identical source, context and execution settings share the existing request journal and completed results with manual reviews. Source changes are checked again before model admission.

Save and Stage use the same background service as Commit and Push. While this extension is connected, Save events carry the observed file hash and their manual/Auto Save/external origin. The service does not authorize unclassified filesystem events while an editor session is attached. Repeated external events cannot authorize the bytes of an Auto Save that was already excluded. Typing cancels pending work for that file.

After the last editor disconnects normally, external watching continues only if **Include external file changes** is enabled. An already accepted Save continues even when external watching is off. Stage continues to observe the actual index independently of VS Code. New service watches baseline the current state; repeated configuration retains pending observations.

A dead editor process can leave writes whose Save origin was never delivered. The service records these as unclassified and the extension asks for a manual review of the current files. It does not replay the uncertain writes automatically. The service’s `watch status` shows the last editor transition and the unclassified paths. Registration before editor activation and failures during that handoff still require further lifecycle verification.

Newly completed Save/Stage reports can update Problems and inline comments only while the workspace/profile/connection is still selected and the saved source matches the current editor or file. A newer manual review keeps priority in the display. Opening saved history does not automatically restore old diagnostics.

## Commit and Push

Commit captures Git's actual index, including the temporary index used by a partial commit or amend. Push captures each old/new object pair from pre-push stdin. Both submit encrypted snapshots to an independent local service. Git returns after durable enqueue; model completion is a separate result. The service continues when the hook or extension exits. Results appear in review history, refreshed while the extension is open.

Set `commitDefender.serviceNodePath` in User Settings to a Node.js 22+ executable if `node` on PATH is older or unavailable. The CLI and hook adapter are copied into private storage by content hash, so an extension directory update does not remove their entrypoints. The service uses the selected Codex executable, model and reasoning setting from User Settings. Background registration currently requires the supported Codex executor; manual API-provider support does not imply automatic-service support. An existing service without automatic-budget or editor-event support must be stopped after its active reviews finish before starting the bundled version. OS login startup is not yet configured.

Existing hooks remain at their original paths and are invoked with their arguments, environment, output and exit status. A private forwarding directory is selected by the repository's `core.hooksPath`; global configuration is not edited. With shared repository configuration, worktree routes restrict automatic enqueue to explicitly enabled worktrees. Existing worktree-specific configuration is used when enabled. Removing the final route restores the previous local setting. If another tool changes the forwarding files or hooksPath, removal reports a conflict and preserves those changes.

The original hook runs first. Its failure still stops Git and prevents automatic enqueue. Review findings, unavailable service or model failure do not block a successful original hook. `commitDefender.hookReviewWaitSeconds` optionally waits for a result (default 0, maximum 600 seconds); its timeout does not cancel the service job or alter Git's exit policy. An enqueue observation failure prints its request ID for reconciliation and is never automatically retried.

Hook resolution follows [Git's hook contract](https://git-scm.com/docs/githooks) and [hooksPath rules](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corehooksPath). These adapters preserve the existing legacy Commit Defender hook too; enabling both can invoke that legacy review before the new background review. Disable the legacy hook explicitly if you no longer want its review/blocking policy.

## Current limits

Whole-file and partial-hunk unstaging do not create a new Stage review. A pending Stage that has not been submitted yet keeps its earlier authorization for the remaining staged content. Unstaging after submission cancels obsolete queued/running work without starting a replacement. New edits mixed with an unstage still schedule a review. Older watch records establish their missing blob history on the first observation and retain earlier pending paths; changes from before that baseline are not guessed. Open a nested Git repository as its own workspace folder to give it a separate event observer. Automatic service configuration currently requires an online central selection when using centralized mode. The service uses the explicitly registered CD client binding for that connection; ordinary CLI commands still require a CLI binding. User-wide token budgets, retention and complete editor-startup/crash recovery remain pending. Interrupted jobs with saved reports can be inspected with **Commit Defender: Recover Background Review**.

Select the account, model and review mode using the existing review settings. Enabling a trigger does not configure an account or grant additional source/tool access. An unavailable source or execution error is recorded in Commit Defender Output; automatic execution does not open account prompts.
