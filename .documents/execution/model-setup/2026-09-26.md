# 계정·API 모델 설정 흐름 개편

계정 선택에서 모델 ID를 직접 입력하던 흐름을 실제 계정 catalog 선택으로 교체했다. Command Palette와 영문·국문 내장 Walkthrough의 진입점은 `Commit Defender: Use Account`, `Commit Defender: Use API Credential` 두 가지다. 기존 command ID는 링크 호환성을 위해 유지한다.

## 사용 절차

- **Use Account**: Codex / Claude Code / Antigravity 선택 → 기존 CLI 인증과 연결 확인 → 반환된 모델 목록 선택 → 지원 effort 선택 → User Settings 저장.
- **Use API Credential**: API provider 선택 → endpoint → model 또는 Azure deployment name → 지원 effort → API key 입력 또는 해당 destination의 저장된 키 재사용 → User Settings 저장.

계정 조회 실패 시 Retry, Sign In, Open Settings를 제공한다. Sign In은 기존 CLI 로그인 터미널을 열며 로그인 완료 후 Use Account를 다시 실행한다. auth.json의 파일 유무만으로 성공을 판정하지 않는다. Codex의 파일/OS 인증, Claude Code와 Antigravity의 OS credential store를 각 CLI가 읽고 연결을 확인한다. 인증 내용을 CD 설정에 복사하지 않는다.

Azure에서는 deployment name만으로 모델을 추정하지 않고 실제 underlying model을 선택적으로 입력받는다. 현재 API adapter가 지원하고 공식 문서에 명시된 모델의 effort만 제시한다. 지원 불명, 임의 compatible endpoint, effort를 전송하지 않는 adapter는 server default를 사용한다. API 설정은 로컬 credential 저장·binding을 검증하며 실제 endpoint의 권한·모델 접근 가능성은 리뷰 실행 시 확인한다. 설정 과정의 유료 생성 probe는 없다.

모델 API key는 GCR reader key와 별개임을 입력 화면에 표시한다. 기존 destination-bound 암호화 저장소와 명시적 plaintext migration을 재사용한다. `Existing keys and plaintext migration…`에서 기존 관리 화면에 접근할 수 있다.

## 구현과 보존

- 사용자 설정의 CLI executable만 사용한다. 저장소 설정으로 인증용 실행 경로를 바꾸지 않는다.
- Codex는 `account/read`, `account/rateLimits/read`, `model/list`를 호출한다. 기존 executor의 지원 버전 0.153.4 / 0.154.0과 bundled descriptor를 대조한다. 고정 source executor의 기존 지원 범위에 맞춰 최대 xhigh까지 제시한다.
- Claude Code는 `auth status`와 SDK control protocol의 `initialize`, `get_usage`를 사용한다. 사용자 prompt, turn, tool, MCP 실행을 요청하지 않는다.
- Antigravity는 `agy models`가 반환한 ID만 사용한다. low/medium/high 등의 실제 variant를 모델별 effort 선택으로 묶고, 선택한 variant의 정확한 ID를 저장한다. 별도의 미지원 `--effort` override를 보내지 않는다.
- 조회에는 기존 bounded managed process를 재사용한다. 명령당 30초, 출력 2 MiB 한도와 취소, POSIX process group / Windows Job Object 정리를 유지한다.
- 조회 실패·빈 catalog에 정적 모델 목록을 대입하지 않는다. Antigravity의 일반 연결 실패를 인증 정보 부재로 단정하지 않는다.
- 입력·조회 중에는 기존 설정을 변경하지 않는다. 모든 선택 완료 후 provider를 마지막에 저장한다. 저장 중 리뷰 준비·hook 동기화는 직전의 완전한 설정을 유지한다. 동시 사용자 변경을 감지하며 rollback도 이 작업이 쓴 값에만 적용한다.
- GCR 요청·review provider 실행 경로·공통 package·자동 실행 설정·전역 CLI 설치는 변경하지 않았다.

Host 설정 흐름 검증은 source harness에서 picker 답변만 자동 제공하고 packaged worker를 호출했다. 실제 CLI 인증·서버 조회·VS Code 설정 API를 사용했지만 **완전한 picker 화면 조작·rendering 검증 또는 실제 리뷰 생성 증거로 취급하지 않는다**. 패키지 활성화와 command 등록은 실제 packaged extension을 대상으로 확인했다.

분리된 native UI 창의 초기 실행은 macOS IPC socket 경로 길이 제한에 걸려 짧은 임시 경로로 변경했다. UI 자동화에서 동일 bundle ID의 여러 Code 인스턴스를 안정적으로 구분하지 못해 전체 화면 조작 검증은 완료로 기록하지 않는다. 첫 Host harness에서도 extension별 VS Code API 객체가 분리되어 native picker에서 대기했고 종료했다. 이후 해당 test extension의 API로 같은 source 흐름을 실행하는 harness로 수정해 Source/Frozen Host 검증을 완료했다.

리뷰 생성 호출은 이번 작업 전체에서 0회다. API credential 신규 발급·production 임시 reader key 생성·PR 댓글 발행도 없었다. Windows/Linux 실제 OS 실행과 API endpoint의 실제 모델 요청은 이번 검증 범위에 포함하지 않는다.

## Reference와 적용

reference-led-frontend 및 agent-skills의 product-ui-ux-design / frontend-development / web-publishing 지침을 사용했다. [VS Code Quick Pick 가이드](https://code.visualstudio.com/api/ux-guidelines/quick-picks)의 native 선택·명확한 title/detail·여러 단계 구성을 적용했다. 별도의 webview·배너·카드 UI는 추가하지 않았다. 긴 연결 조회에는 취소 가능한 진행 표시, 실패에는 재시도/로그인/설정 동작을 제공한다.

프로토콜·capability 근거는 [Codex app-server](https://learn.chatgpt.com/docs/app-server), 설치된 Claude Code SDK의 control protocol와 [공식 SDK 변경 기록](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md), [Antigravity CLI reference](https://antigravity.google/docs/cli/reference/), [OpenAI reasoning 문서](https://developers.openai.com/api/docs/guides/reasoning), [GPT-5.5 capability](https://developers.openai.com/api/docs/models/gpt-5.5)를 참조했다. 문서상의 가능성과 실제 계정이 반환한 catalog를 구분한다.
