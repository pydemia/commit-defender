# P10 실행 기록

## 철회 — 2026-09-15

사용자가 중앙→로컬 리뷰·프롬프트 단방향 전파와 로컬 모델 실행을 명확히 지시했다. 이 문서 아래의 중앙 실행 개발·설치 기록은 과거 기록이다. 중앙 실행·source 업로드·결과/피드백 제출을 현재 요구사항이나 완료 목표로 해석하지 않는다. 중앙 실행 배포는 하지 않았고 실제 사용자 중앙 모델 호출은 0회다. 2.9.0의 잘못 추가한 선택 기능과 준비 중이던 worker 변경을 제거하고 로컬 실행 설치본으로 교체한다.


## Commit Defender 중앙 실행 UI와 2.9.0 설치 — 2026-09-15

수동 staged 리뷰에서 local/central 실행기를 선택하고 중앙 server·account·model·effort를 고른 뒤 고정된 source/context와 예산·보존 기간을 확인해 전송하도록 연결했다. 승인 hash가 일치해야 요청을 보내며 응답 유실·재시작 뒤에는 같은 요청의 상태·결과·취소를 조회한다. 기존 summary·findings·세션 history에 중앙 결과를 표시한다. 중앙 리뷰의 재분석과 feedback 재리뷰도 중앙 실행 선택과 새 승인을 거치고 필요한 중앙 기준이 바뀌면 중단한다. 로컬 provider로 암묵적으로 바꾸지 않는다.

Client alpha.33과 CLI alpha.29를 고정한 CD 2.9.0을 패키징했다. 회귀 206개가 통과했다. 처음 여섯 suite의 79개 통과 뒤 delivery pin/provenance 누락으로 중단됐으며 실제 source commit과 package hash를 기록한 후 해당 suite부터 나머지 127개를 통과했다. 실패·반복 건수를 합산하지 않는다. 마지막 UI 반복 검사, source/test typecheck와 build가 통과했다. Chrome에서 실제 CSP 아래 승인 hash·취소·escaped source 표시를 확인했고 문자 인코딩 문제를 UTF-8 선언으로 수정했다.

최종 VSIX를 별도 사용자 데이터 디렉터리로 실행한 VS Code 1.90.2와 1.135.0에서 활성화·28개 명령·자동 실행 기본값·빈 history의 OS key 미생성을 확인했다. 실제 native 창에서 중앙 모델 리뷰 전체를 실행했다는 증거는 아니다. 기존 2.8.1을 백업하고 2.9.0을 설치했으며 37개 파일과 VS Code metadata를 제외한 package 내용이 VSIX와 일치한다. 사용자 창의 강제 reload와 전역 CLI 교체는 하지 않았다.

실제 사용자 계정 모델 호출은 0회이며 PRISM 서버는 기존 배포를 유지한다. Docker 저장소 I/O 오류 이후 이미지 빌드 성공은 아직 확인하지 못했다. 중앙 준비의 source capture는 현재 extension host에서 실행되어 큰 저장소의 응답성을 더 보완해야 한다. 복구 명령은 서버 보존 기간 내 검증된 summary를 열며 local conversation/captured-source history 복원은 포함하지 않는다. P10과 P00–P13의 나머지 완료 조건은 유지한다. [검증·설치 기록](evidence/P10-central-model-ui.json)에 SHA와 로그 범위를 기록한다.
