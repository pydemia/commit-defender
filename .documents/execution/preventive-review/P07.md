# P07 실행 기록

## 공통 실행 기록 연결

확장의 fixed-source worker를 GCR `executeReviewRequest`에 연결했다. `@gcr/client-*`는 `0.1.0-alpha.18`, source pin은 GCR `d808543`이다. CLI `0.1.0-alpha.12`와 같은 local data directory·profile·repository·worktree를 사용하면 동일한 source/context/model/tool 설정의 요청을 합치고 저장된 보고서를 재사용한다. 재사용 여부는 결과 진단에 표시한다.

두 개의 독립된 준비 작업과 새로 시작한 worker가 같은 실행 기록을 읽는다. 중앙 이력을 재사용할 때도 현재 접근 권한을 검사한다. 결과 저장 실패 시 보고서를 버리지 않고 저장 여부가 미확정임을 표시한다. 실행 중 프로세스가 사라진 요청은 `interrupted`로 남으며 자동 재호출하지 않는다.

실행권을 기다리다가 취소된 호출자는 자기 취소·시간 초과 보고서만 저장한다. 다른 호출자가 소유한 요청을 완료하거나 취소하지 않는다. 실행 전에 이미 취소된 신호를 받은 경우에도 모델을 호출하지 않는다.

## 검증 범위

모의 executor로 같은 입력의 동시 실행·새 준비 작업 재사용, 취소된 대기자와 실행 소유자의 분리를 검사한다. 실제 계정 smoke는 합성 TypeScript 저장소에서 모델 리뷰 한 번을 실행한 뒤 새 확장 worker와 설치한 CLI가 정확히 같은 보고서를 재사용하는지 확인한다. 실제 모델은 `gpt-6-astra / xhigh`다. 테스트 profile의 Keychain 항목과 로컬 기록은 종료 시 제거한다.

버전별 VSIX·테스트·실제 계정 검증 결과는 `evidence/P07-requests.json`에 기록한다. Marketplace에는 발행하지 않았다. 기존 사용자 설치 파일을 백업한 뒤 최종 VSIX를 설치했고 설치된 세 bundle이 VSIX와 byte 단위로 같은지 확인했다. 열려 있는 사용자 창은 강제로 재시작하지 않았으며 새 코드를 로드하려면 Reload Window가 필요하다.

## 남은 구현

Save·Stage 이벤트를 새 scheduler에 연결하고 네 toggle·repo override·최소 간격·예산 UI를 구현해야 한다. 기존 Stage watcher는 남아 있으며 아직 Stage 사유를 전달하지 않는다. 별도 headless service와 사용자 전용 IPC, exact commit/push source, 비파괴 hook 설치도 미완료다. 현재 실행 기록은 살아 있는 호출자가 이미 준비한 source를 공유 실행하는 범위이며 P07 전체 완료를 뜻하지 않는다.

최종 회귀 검사는 145 passed, 0 failed이며 source/test TypeScript 검사도 통과했다. VS Code 1.90.2와 1.137.0의 독립 native host에서 최종 패키지 활성화·22개 command·기본 standalone 설정·빈 이력의 무접속 동작을 확인했다. 최종 실제 계정 검사는 completed 보고서와 finding 1개를 생성했고 새 worker와 설치한 CLI가 같은 보고서를 재사용했다. 취소 처리 수정 전후 checkpoint에서 각각 모델 리뷰 한 번, 총 두 번을 실행했다.

## Save·Stage 이벤트 연결

Save와 Stage를 공통 GCR scheduler/worker에 연결했다. 사용자 설정과 extension global state의 worktree별 override만 자동 실행을 허용한다. 기본값은 모두 off이며 Auto Save·외부 변경도 별도 opt-in이다. Global pause는 worktree override보다 우선한다.

Save는 저장 바이트·HEAD를, Stage는 실제 index fingerprint·HEAD 및 snapshot의 Git blob OID를 모델 실행 전에 다시 확인한다. Debounce는 3초, Save 최소 간격은 기본 10분, 자동 실행은 profile/worktree당 시간당 기본 6회다. 후자는 리뷰 시작 수이며 provider API 호출/토큰 수가 아니다. 수동 실행은 자동 제한으로 차단하지 않는다. 최신 요청 교체와 취소 뒤 늦은 결과는 화면을 갱신하지 않으며 자동 리뷰는 summary 열기·편집기 이동을 수행하지 않는다.

GCR `41432d2`의 client 라이브러리 alpha.19 tarball을 vendor에 고정했다. 개발 중 복사한 dist 대신 실제 tarball을 설치해 빌드와 source/test TypeScript 검사를 수행했다. 실제 package의 Save·Stage 모델 검증 및 설치 결과는 다음 기록에 별도로 추가한다.

독립 background service, Commit·Push trigger와 toggle, 사용자 전체 예산, 부분 hunk unstage 구별, host 종료 중 누락 이벤트 복구는 미완료다. 이번 Save·Stage 네 설정 조합을 전체 네 trigger의 16개 조합 검증으로 간주하지 않는다.

## Commit·Push 사용자 설정과 비파괴 hook 연동

User Settings와 worktree별 extension user state에 Commit·Push toggle을 추가했다. Save·Stage와 독립적으로 선택하며 신규 네 toggle은 모두 off다. `Automatic Reviews` 메뉴에서 선택할 수 있고 repository 설정은 실행 권한을 추가하지 못한다. 선택한 user Codex/model/effort와 중앙 연결을 독립 서비스 등록에 반영하며 기본 시간당 한도 6회를 공통 profile/worktree 실행 기록으로 적용한다.

확장은 GCR client alpha.22와 CLI alpha.16 artifact를 pin한다. CLI·advisory adapter는 private data directory에 content hash별로 복사하므로 extension 설치 경로가 바뀌어도 hook 진입점이 남는다. Node.js 22 이상이 필요하며 `serviceNodePath`는 User Settings에서만 읽는다. 서비스 기능 표시로 시간당 한도 지원을 확인하고 지원하지 않는 이전 서비스에는 자동 hook을 새로 연결하지 않는다.

기존 hook 파일은 수정·이동·삭제하지 않는다. Git이 해석한 hook 경로를 원본으로 보관하고 별도 forwarding directory를 local hooksPath에 연결한다. 원본 hook을 먼저 실행해 인수·stdin·stdout·종료 코드를 보존한다. 실패한 기존 hook 뒤에는 리뷰를 접수하지 않는다. Pre-push stdin은 private 임시 파일로 전부 전달하고 접수 뒤 정리한다. Git 진행과 모델 결과는 분리하며 `hookReviewWaitSeconds`의 기본값 0은 접수 뒤 즉시 반환한다.

공유 Git 설정을 사용하는 linked worktree는 공통 forwarding directory 안에서 명시한 worktree만 리뷰하도록 route를 분리한다. 기존 worktreeConfig가 활성화된 저장소는 해당 config.worktree를 사용한다. 마지막 route를 제거하면 이전 local hooksPath 값을 복원하며 외부 도구가 설정이나 관리 파일을 바꿨다면 보존하고 충돌을 보고한다. 전체 일시정지는 확장이 저장한 hook 등록을 폐기한다. 서비스가 정지된 경우에는 live owner가 없는지 확인한 뒤 암호화 등록을 갱신한다.

확장 전체 회귀 검사 160개가 통과했다. 이후 worktreeConfig 전용 경로 검사 1개를 추가하고 managed hook 검사 6개를 다시 통과했으므로 검증한 고유 검사는 161개다. 설정의 16개 toggle 조합을 확인했으며 이것을 네 trigger 전체의 조합별 실행 검증 완료로 계산하지 않는다. Source/test TypeScript 검사와 bundle/VSIX 제작도 통과했다.

최종 VSIX SHA-256은 `4d1898d36b1faf67c7926ec3e4287feb59ceaa7fd61e35f6f9c22c7da1507d37`다. VS Code 1.90.2(Node 20.9.0)에서 활성화·23개 command·빈 이력의 OS key 미생성을 확인했다. VS Code 1.137.0에서는 별도 사용자 프로필에서 Commit·Push를 켜 실제 모델 리뷰를 수행했다. 두 Git 명령이 반환될 때 receipt는 running이었고 각 리뷰가 completed·finding 1개·source-read 7건을 기록했다. `gpt-6-astra / xhigh`를 사용했으며 모델이 테스트 명령을 실행한 것은 아니다.

부분 commit의 source tree 일치와 관련 없는 staged 변경 보존, 전체 일시정지 뒤 권한 폐기와 hooksPath 복원을 확인했다. 테스트 서비스를 종료한 뒤 해당 profile의 기본·review-requests·local-service OS key와 암호화 기록을 정리했다. 이전 사용자 확장을 백업하고 같은 VSIX를 설치했으며 extension/hook/worker/advisory/CLI bundle 및 CLI manifest가 검증본과 byte 단위로 일치한다. 열린 사용자 창의 reload는 강제하지 않았다.

P07 전체 완료는 아니다. 네 trigger 조합별 실제 실행·중복 경로 검증, 사용자 전체/token 예산, headless 파일 감시·OS 로그인 lifecycle, partial-hunk unstage, closed-host 누락 이벤트와 interrupted 결과 대조·receipt 보존 정책이 남아 있다. 다른 UID의 실제 IPC 거부 검증도 남아 있다. Save·Stage는 현재 확장 host를 사용하며 Commit·Push의 중앙 모드는 online 선택만 연결한다. 공개 Marketplace 게시 및 PRISM 서버 변경은 이번 client 전달 범위에 포함되지 않는다.

## 중단된 background 리뷰의 결과 복구

Commit Defender 2.6.0에 `Recover Background Review` 명령과 클릭 가능한 interrupted 상태 표시를 추가했다. 완료 여부가 확인되지 않은 receipt에 run ID가 있어도 finished로 표시하지 않는다. 사용자가 선택한 원래 workspace/profile, 확장의 소유 등록, 현재 registration revision/trigger를 확인하고 서비스에 job ID만 전달한다. 복구한 partial/failed 결과는 원래 상태를 유지한다. 저장 근거가 없으면 interrupted로 남으며 모델을 새로 실행하지 않는다.

GCR `dbd7a46`의 client alpha.27과 CLI alpha.23 불변 artifact를 vendoring했다. 실행 중인 구형 서비스는 교체·종료하지 않으며 recovery capability가 없으면 활성 작업 종료 후 재시작 절차를 안내한다. Package와 lockfile, service bundle hash 및 배포 provenance를 갱신했다.

확장 고유 회귀 검사 185개와 source/test 타입 검사, bundle·VSIX 검증을 통과했다. 최초 전체 실행은 이전 alpha.26 버전 기대값에서 실패했으며 해당 delivery pin을 alpha.27로 갱신한 뒤 그 suite와 나머지 suite를 완료했다. 기존 report corpus와 hash 검사는 유지했다.

최종 VSIX를 풀어 VS Code 1.135.0에서 실제 interrupted 표시→복구 작업 선택→완료 메시지와 원래 run ID/source hash 복원을 확인했다. 합성 executor는 한 번 실행됐으며 OS Keychain·암호화 이력·실제 IPC를 사용했다. 검증은 저장된 요청이 완료됐지만 서비스 receipt만 미확정인 상황을 주입했다. 모델 재호출이나 현재 작업 파일 재수집은 없었다. 같은 VSIX의 최소 VS Code 1.90.2 활성화와 26개 command, 빈 이력의 key 미생성도 확인했다.

첫 화면 검증은 복구 자체를 확인했으나 알림 닫기 선택자가 timeout으로 실패했다. 같은 host에서 해당 알림을 닫고 host 종료를 확인한 뒤 key 3개와 fixture를 정리했으며 원래 실패 증거를 보존했다. 선택자를 수정한 최종 VSIX 실행은 전체 통과했고 별도 테스트 프로필의 서비스·native host·key 3개·파일 정리를 마쳤다. 상세 범위와 SHA는 `evidence/P07-CD-recovery.json`에 기록했다. 사용자 설치는 이 checkpoint의 후속 전달로 기록한다.

P07의 나머지 trigger 실행 조합·headless 감시·누락 이벤트·사용자 전체 예산·보존 정책·다른 UID 검사와 P03–P06, P09–P13의 잔여 조건은 계속 남아 있다.

소스 `80f3598`을 원격 branch에 push한 뒤 기존 사용자 설치본 2.5.0을 백업하고 검증한 2.6.0 VSIX를 설치했다. VSIX SHA-256은 `2fd1469ca48e02e7876e3629a39f3e48a26bd74e718edcb41cff9d831d0dfccd`다. 설치된 확장·worker·hook·advisory·CLI와 manifest 총 7개 파일이 검증본과 byte 단위로 일치한다. 사용자 창 reload, global CLI 교체, PRISM 서버 rollout은 수행하지 않았다. 열린 창이 새 확장을 로드했는지는 설치 성공과 구분한다.

## Stage 누락 이벤트와 대기 작업의 재시작 복구

Commit Defender 2.7.0은 worktree/profile별 마지막 index 관측값과 처리 대기 경로를 기존 암호화 local store의 settings record에 저장한다. 확장 시작과 focus 복귀 때 현재 HEAD·index를 대조한다. Stage가 계속 켜져 있던 동안 새로 staged된 변경과 host 종료 당시 대기 중이던 변경을 공통 scheduler에 다시 전달한다. 처음 켜거나 실행 선택을 바꾼 시점은 새 baseline으로 삼으며 과거 이벤트를 추정하지 않는다. 전체 파일 unstage, 변경 없는 index, Stage off/pause로 폐기한 대기는 새 리뷰를 만들지 않는다.

Worker가 보고서 저장과 공통 요청 완료를 모두 확인한 경우에만 관측 기록의 대기를 지운다. 이전 fingerprint에 대한 완료 응답은 더 최신 대기를 지우지 못한다. 관측 기록의 저장 실패 뒤 재시작하면 공통 broker가 원래 저장된 보고서를 재사용하며, 관측 기록을 별도 실행 lease로 사용하지 않는다. 취소된 refresh의 기록 쓰기는 generation을 다시 확인한다. Save 동작과 Commit/Push 서비스 설정은 기존 경로를 유지한다.

확장 고유 회귀 검사 195개, source/test 타입 검사, 최종 VSIX bundle/manifest 7개 파일 대조를 통과했다. 새 검사는 closed-host Stage, 수동 작업 뒤 대기 복구, focus 시 누락 보정, 전체 파일 unstage, toggle off/on, 과거 acknowledgement의 fence, 미확정 완료 보존을 포함한다. 보고서 저장 후 관측 기록 갱신 실패를 주입한 실제 공통 broker 통합 검사에서는 같은 run ID를 재사용했고 합성 executor는 한 번만 실행됐다. 별도 history/request 저장 실패 검사도 완료 확인값이 false임을 검증했다.

실제 VS Code 1.135.0에서 Stage를 켠 첫 baseline을 저장하고 host 종료 뒤 결함을 stage했다. 다시 연 확장이 현재 계정 `gpt-6-astra / xhigh`로 84,970 ms에 completed 보고서와 결함 1개를 저장했다. Source/base·관련 코드·테스트 파일을 포함한 source-read 근거 8개가 남았으며 테스트 명령 실행을 주장하지 않는다. 관측 대기도 비워졌다. 실제 모델 실행은 한 번이다.

첫 native 검증 도구는 `/var` URI로 진단을 조회했지만 자동 리뷰는 canonical `/private/var` 경로를 사용해 진단 표시 assertion에서 대기했다. 모델과 공통 요청·관측 기록이 완료된 것을 확인한 뒤 해당 observer와 native host만 종료하고 원래 profile을 보존했다. 원래 실행 소스·보고서·관찰 중단 근거를 보관했으며 검증 코드는 realpath를 사용하도록 고쳤다. 원래 profile과 같은 최종 VSIX로 재시작 검사를 이어서 완료했고 run ID `870145ea-3536-4dce-8d39-b02bef07c737`, 요청 generation 1이 유지됐다. 새 모델을 호출하지 않았다. 첫 도구 전체나 도달하지 못한 진단 표시 assertion을 통과로 기록하지 않는다.

같은 VSIX의 최소 VS Code 1.90.2 활성화와 26개 command, 빈 profile의 key 미생성을 확인했다. 마지막 native 실행에서 추적한 소유 프로세스 29개가 모두 종료됐고 key 2개와 원래 fixture를 정리했다. [검증 증거](evidence/P07-CD-stage-catchup.json)에 원래 모델 실행, 관찰 도구 한계, 재시작 확인과 정리를 분리했다. 사용자 설치는 후속 전달로 기록한다.

P07 전체 완료는 아니다. 네 trigger의 전체 실행 조합과 실제 중첩 경로, closed-host Save·headless 감시, partial-hunk unstage, 사용자 전체 예산·보존 정책·다른 UID IPC 및 원래 P03–P06·P09–P13의 잔여 조건이 남아 있다.
