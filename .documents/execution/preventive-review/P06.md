# P06 — Commit Defender 중앙 리뷰 연결

## 2026-09-14 — 연결 UI와 공통 worker

GCR `a81d2c2`의 client package alpha.14를 사용하는 worker에 명시적 중앙 모드를 연결했다. 기존 source/base snapshot과 실행 승인, 모델 adapter, report projection을 공통으로 사용한다. 중앙 모드는 선택한 connection ID와 online/offline freshness를 요구하며, 연결·프로필·worktree·client ID를 검증한 뒤 중앙/로컬 context를 구성한다. 실패한 중앙 요청을 standalone으로 자동 전환하지 않는다.

`Central Review Connection` 명령과 sidebar 항목을 추가했다. 관리자가 제공한 공개 설정 JSON을 선택하고 서버·tenant·repository·서명 키 fingerprint를 확인한 뒤 password 입력으로 API key를 받는다. Key는 기존 OS credential store에 저장하고 worker에는 연결 ID만 전달한다. 선택한 mode/connection은 extension global state에서 profile·repository·worktree hash별로 보관한다. Repository settings는 이 선택을 변경하지 못한다.

UI에서 기존 연결 선택, read-only 상태, 수동 sync, 명시적 offline 선택, standalone 선택, disconnect를 수행한다. Status는 실제 server/user/repository, key expiry, signed bundle release/hash와 refresh/offline 만료 시각을 보여준다. Mode/connection을 바꾸면 기존 실행과 표시 결과를 정리한다. Disconnect는 중앙 cache와 key를 폐기하고 선택 mode는 유지해 다음 리뷰가 연결 끊김을 알리도록 한다. Standalone 전환에는 별도 사용자 선택이 필요하다.

중앙 결과는 audience별 별도 암호화 history에 저장한다. 재조회와 in-memory 병합 모두 mode·server·tenant·repository·user·profile·worktree를 검사한다. Local Memory/Skills는 함께 적용하고 수정본을 보존한다. 요약 화면은 중앙 mode와 snapshot audience/provenance를 표시하며 이력의 과거 snapshot을 현재 인가 상태로 표현하지 않는다. 기존 provider hook과 commit-message 경로는 유지한다.

일반 회귀 134건이 통과했다. 새 central review 6건은 실제 임시 Git·HTTPS·서명 bundle과 주입한 key store/모델로 혼합 context, 이력 격리, standalone의 무통신, offline, 확인한 403의 차단, disconnect 중 취소·늦은 source read 거부를 확인한다. 연결 UI 3건은 VS Code API mock과 실제 HTTPS listener로 password 입력·선택 저장·sync·상태·전환·해제·HTML escaping을 검사한다. 첫 실행의 3건 실패는 테스트 key store가 read에서 내부 Buffer를 그대로 돌려주어 store close의 메모리 정리가 저장된 fixture key까지 지웠기 때문이었다. read가 복사본을 반환하도록 수정한 뒤 모두 통과했다.

실제 macOS Keychain과 패키징한 worker에서는 현재 Codex 0.154.0·gpt-6-astra/xhigh로 중앙 계약 위반을 찾아 completed report를 받았다. 처음 검증은 약 85초였으며 source/base와 호출부·테스트 소스를 읽고 중앙 정책 참조를 인용했다. 별도 부모 runtime에서 암호화 이력을 동일하게 복원하고 disconnect 후 조회 거부와 테스트 key 제거를 확인했다. 합성 HTTPS 서버와 합성 코드만 사용했으며 PRISM-DEV의 실제 중앙 API를 검증한 것은 아니다.

실제 VS Code 1.90.2와 1.137.0 Extension Host에서 확장 활성화, 22개 command 등록, standalone 기본값, 빈 history가 OS key를 만들지 않는 조건을 확인했다. 연결 dialog의 화면을 직접 조작한 시각 검증과 구분한다. 개발용 `2.3.0` VSIX를 생성하고 내부 extension/hook/worker가 빌드 결과와 같은지 검사했다. VSIX에서 추출한 확장의 1.137.0 Host 활성화도 통과했다.

실행 기록과 source/artifact hash는 [검증 증거](evidence/P06-connected-review.json)에 보관한다. 사용자 안내는 [중앙 리뷰 문서](../../../vscode-extension/docs/central-review.md)에 있다. P06-C05 구현 checkpoint이며 P06 전체 완료가 아니다. Remote 자동 매핑, 주기 sync/backoff/자동 fallback, 중앙 자료 본문 UI와 export 인가, PRISM-DEV v2/API key 배포 및 실제 서버 연결, Linux 실행 검증은 남아 있다. Marketplace 게시나 사용자 VS Code 설치본 교체를 수행하지 않았다. 전체 P00–P13 goal은 진행 중이다.

최종 VSIX의 worker SHA-256과 실제 계정 smoke가 기록한 실행 파일 hash가 일치한다. 이 worker의 중앙 리뷰는 약 65초 만에 completed·결함 1건·exit 1로 끝났고 전체 이력 복원·disconnect·테스트 key 제거가 통과했다. VSIX의 extension과 hook/worker bundle도 빌드 파일과 일치한다. 모델 검증은 source build와 VSIX에서 각각 1회씩 실행했으며 두 결과 모두 보존했다.

## 2026-09-14 — 초기 발행 대기와 PRISM-DEV 실제 리뷰

공통 client package alpha15를 고정하고 신규 저장소의 초기 지식 발행을 기다리도록 연결 동작을 보완했다. 실제 HTTP 503 manifest 응답에만 증가하는 간격과 jitter를 적용하며, 초기 sync는 최대 60초다. 연결 상태와 cache 실행권은 pending으로 유지하고 서명된 세 component의 검증이 끝나야 활성화한다. 취소·timeout·실패에서는 등록 중인 key를 제거한다. 진행 알림에서 대기 중임을 표시하고 취소를 유지한다.

전체 회귀 134건과 build/test typecheck를 통과했다. 새 개발 VSIX를 추출해 VS Code 1.90.2(Node 20.9.0)와 1.137.0에서 실제 활성화·22개 명령·빈 이력의 OS key 미생성을 확인했다. 패키지의 세 bundle은 checkout 빌드와 바이트가 같고 source/test/vendor는 제외했다.

PRISM-DEV runtime alpha42에 검증용 개인 memory를 만들고 projection을 명시적으로 승인했다. 같은 서버의 공개 연결 설정과 별도 pin을 대조한 뒤 VSIX의 native worker를 실행했다. 첫 연결 명령 1회가 약 14초 후 완료됐으며 외부에서 준비 상태를 polling하거나 재연결하지 않았다. 현재 계정의 gpt-6-astra/xhigh가 고정 source/base, caller, test를 읽고 중앙 memory의 계약 참조를 인용해 cents를 dollars로 변환하는 합성 오류를 지적했다. report는 completed, finding 1개, source read 6개다. 부모 프로세스에서 암호화 이력을 정확히 복원했고 disconnect 후 접근 거부를 확인했다. 시험용 서버 행·OS key·로컬 파일은 정리했다.

실제 모델 실행은 패키지 worker 검증이며 VS Code 연결 dialog를 클릭해 실행한 UI 검증은 아니다. 사용자 VS Code 설치를 교체하거나 Marketplace에 게시하지 않았다. 주기 sync·automatic fallback·remote 자동 매핑과 후속 phase는 남아 있다. [증거](evidence/P06-PRISM-initial-publication.json)를 참고한다.
