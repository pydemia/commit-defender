## 2026-09-14 — 연결 UI와 공통 worker

`Central Review Connection` 명령과 sidebar 항목을 추가했다. 관리자가 제공한 공개 설정 JSON을 선택하고 서버·tenant·repository·서명 키 fingerprint를 확인한 뒤 password 입력으로 API key를 받는다. Key는 기존 OS credential store에 저장하고 worker에는 연결 ID만 전달한다. 선택한 mode/connection은 extension global state에서 profile·repository·worktree hash별로 보관한다. Repository settings는 이 선택을 변경하지 못한다.

UI에서 기존 연결 선택, read-only 상태, 수동 sync, 명시적 offline 선택, standalone 선택, disconnect를 수행한다. Status는 실제 server/user/repository, key expiry, signed bundle release/hash와 refresh/offline 만료 시각을 보여준다. Mode/connection을 바꾸면 기존 실행과 표시 결과를 정리한다. Disconnect는 중앙 cache와 key를 폐기하고 선택 mode는 유지해 다음 리뷰가 연결 끊김을 알리도록 한다. Standalone 전환에는 별도 사용자 선택이 필요하다.

중앙 결과는 audience별 별도 암호화 history에 저장한다. 재조회와 in-memory 병합 모두 mode·server·tenant·repository·user·profile·worktree를 검사한다. Local Memory/Skills는 함께 적용하고 수정본을 보존한다. 요약 화면은 중앙 mode와 snapshot audience/provenance를 표시하며 이력의 과거 snapshot을 현재 인가 상태로 표현하지 않는다. 기존 provider hook과 commit-message 경로는 유지한다.

## 2026-09-15 — 중앙 저장소 식별 정보와 로컬 Git remote 연결 검증

Remote가 있는 신규 연결은 key를 저장하기 전에 일치 여부를 검증한다. 연결 후 remote가 바뀌면 offline cache·context·리뷰 준비·중앙 본문 조회를 거부한다. Sync는 중앙 식별 정보의 변경도 검사한다. 불일치 상태에서도 연결 해제는 가능하다. 기존 연결과 remote 없는 저장소는 수동·미검증 상태를 유지하며 자동으로 검증 완료로 바꾸지 않는다. 신뢰한 연결 설정과 일치하는 remote로 명시적 재연결해야 binding을 저장한다.
