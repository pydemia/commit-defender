## C07 통합 구현 checkpoint

작업 경로는 `/Users/a09255/git/commit-defender-preventive-review`, branch는 `feat/preventive-review-platform`, 기준 commit은 `35575ad`다. 기존 원본 checkout `/Users/a09255/git/commit-defender`의 `AGENTS.md`와 phoenix submodule 변경은 보존했다. 이번 확인에서 두 내용의 SHA-256은 이전 기록과 동일했다.

수동 리뷰는 `createReviewBackend`에서 GCR standalone worker로 들어간다. `standaloneReview.ts`가 index/working-tree snapshot, profile·worktree의 암호화 Memory/Skill, context/policy, Codex account executor를 연결한다. 준비한 factory 객체는 worker 안에서 유지하고 종료 report를 공통 contract로 projection한다. 실패·취소를 포함한 admitted report는 암호화 history에 저장한다. 저장 확인에 실패하면 결과를 보존하고 별도 진단을 출력한다. Repository 설정이나 Skill이 실행 권한을 부여할 수 없으며 지원하지 않는 선택에는 provider fallback이 없다.

`ReviewExecutionOwner.prepare`는 비동기 캡처 후 실제 source/context identity로 진행 중인 실행과 중복 여부를 확인한다. 같은 실행의 중복 준비는 worker를 해제한다. 다른 준비가 도착하거나 clear/cancel하면 이전 준비에 취소를 전달하고 늦게 준비된 snapshot을 실행하지 않는다. 기존 실행은 새 준비가 유효한 job을 반환할 때까지 결과 소유권을 유지한다. Worker의 종료 확인 후 실행 promise를 완료하며 extension deactivate는 남은 정리를 기다린다. 준비 단계의 진행 표시와 취소도 연결했다.

사용자 설정의 provider·모델·실행 경로·profile만 standalone 실행에 사용한다. 저장소에만 있는 기존 account 설정은 보존하되 재사용하지 않는다. 기존 account 선택 UI는 User Settings에 저장하며 Codex의 현재 지원 조합 `gpt-6-astra` / `xhigh`를 제시한다. 새 설치의 stage 자동 실행은 꺼져 있고 repository 설정으로 켤 수 없다. 기존 commit-message adapter와 legacy hook은 별도 경로를 유지한다. Hook의 credential 처리는 C08에서 변경한다.

Local Memory and Skills 화면은 profile/worktree 선택, candidate 생성, 편집, 활성화·비활성화·archive·삭제, 명시적인 plaintext export, hash를 검증하는 import를 제공한다. 본문은 CSP가 적용된 textarea에서 편집하며 VS Code 임시 문서나 repository 파일로 자동 저장하지 않는다. 변경에는 core의 revision 검사를 적용한다. 선택한 profile의 encrypted history를 재시작 후 읽을 수 있도록 연결했고 CLI의 다른 프로세스에서 생성한 이력도 명시적으로 refresh할 수 있다. 저장된 working-tree review의 재분석은 기록된 파일 선택을 유지한다.

Summary는 immutable GCR report와 별도로 현재 local entry의 revision·state·expiry를 확인한다. 이 관찰은 사용했던 entry의 최신성 검사다. 새로 추가된 항목까지 포함한 전체 context 재계산을 의미하지 않는다. Source/context hash, criteria revision, source-read provenance·range·hash, anchor 검증과 evidence/counter-evidence 평가를 표시한다. Standalone summary/status bar에는 advisory를 표시하며 grade를 만들어 넣지 않는다.

## C07 source checkpoint — 실제 worker·OS store·설치 검증

2026-09-13에 backend/UI 변경을 source commit으로 묶었다. 앞 절의 실제 모델 0회와 남은 작업 목록은 초기 checkpoint의 기록이다. 현재 증거의 파일 hash·실행 수·검증 범위는 [source-checkpoint](evidence/P02-C07-source-checkpoint.json)에 모았다.

Production worker 실행은 11회였고 그중 3회가 `invalid-output`으로 실패했다. 실패 report도 원래 상태로 encrypted history에 저장됐다. 별도 diagnostic worker 2회는 정상 완료했으나 앞선 실패를 재현하지 못했다. Production raw output을 보관하지 않았으므로 실패 원인을 특정하거나 해결했다고 판단하지 않는다. 자동 재시도나 provider fallback은 추가하지 않았다.

각 표본의 실제 source/base read, 독립 fixture test, 원본 index·source 보존, 별도 CLI/CD 프로세스의 full report 복원, Memory 수정·삭제·비활성화와 context freshness 변화를 검사했다. 모든 실행에서 합성 중앙 listener 요청은 0이었다. Actual Codex `0.153.4`, `gpt-6-astra` / `xhigh`, macOS Keychain과 기본 application-data 저장소를 사용했다. 검사에 사용한 180초 한도와 제품의 단일 파일 기본값 120초를 구분한다. 생성한 test profile·OS key·임시 repo는 정리했다.

이 과정에서 기존 TypeScript 수정 표본의 Number 누적이 `[Number.MAX_SAFE_INTEGER, 2, -2]`를 잘못 계산하는 실제 결함을 발견했다. 모델은 base에도 있던 결함임을 구분했다. 입력 계약을 축소하거나 finding을 제거하지 않고 BigInt 누적으로 수정했으며 양수·음수 중간 overflow 회귀 표본을 추가했다. GCR CLI 표본도 같은 방식으로 수정했고 설치된 alpha.3 CLI의 세 실제 리뷰가 1·0·0으로 완료됐다. 이전 C06·C07 실행 증거는 보존한다.

[Skill interop](evidence/P02-C07-knowledge-interop-macos.json)은 UI가 사용하는 `saveKnowledgeFromEditor`와 실제 Keychain을 거쳐 새 CLI 프로세스에서 candidate·activation·편집·revision 충돌·export/import·비활성화·삭제를 확인했다. Skill은 user-authored/review-only를 유지한다. Export는 새 0600 파일이며 기존 파일을 덮지 않는다. 이 검사의 모델 호출은 0회다.

History refresh 중 완료한 현재 리뷰를 잃지 않도록 merge를 보완했고 다른 profile/worktree 이력을 제외했다. 빈 profile의 sidebar 조회는 storage와 OS key를 만들지 않는다. Worker가 닫힌 뒤에도 선택된 검토 source를 열도록 ephemeral 본문을 반환하고 hash·line count 검증 후 최대 8 MiB 메모리 cache에 넣는다. 본문을 report/history에 추가하지 않는다. 재시작이나 eviction 뒤 복원 가능한 source가 없으면 재검토를 안내한다. [최종 production worker 검사](evidence/P02-C07-worker-source-navigation.json)는 model output validation에서 실패했지만 원본 source 보존, 이력 복원, 변경된 working tree에서 captured source 조회를 확인했다. [별도 diagnostic 검사](evidence/P02-C07-worker-defect-diagnostic.json)는 실제 결함을 완료하고 같은 source 조회도 통과했다. 두 worker의 hash와 검증 범위를 합쳐서 하나의 production 실행으로 취급하지 않는다.
