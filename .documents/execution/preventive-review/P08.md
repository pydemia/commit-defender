# P08 실행 기록

## P08-C02 — Commit Defender 대화 화면과 worker

Summary의 Discuss review, history 항목, command palette에서 원래 보고서의 대화를 연다. Finding 선택은 질문 초안만 만들고 명시적 전송 뒤 모델을 호출한다. Review 요약·finding, 사용자 질문·확인 답변, 모델 답변·source evidence, 실행 상태를 구분한다. Enter 전송, Shift+Enter 줄바꿈과 IME 입력, draft 보존, 질문 저장 후 재개, 명시적 취소·queued resume를 연결했다.

대화 worker는 현재 trusted workspace·profile·connection 선택을 다시 확인한다. 원래 source·context·executor와 승인 정책을 재구성하고 다른 선택이나 변경된 지식에서는 실행하지 않는다. 같은 중앙 publication의 정상 재동기화는 관측 시각만 갱신하므로 원래 identity의 관측 시각을 유지하되 현재 authority와 context를 별도로 검증한다. UI는 provider 비공개 추론 대신 source 조회와 대기·취소 상태를 표시한다. Worker 종료와 자식 프로세스 정리 후에 결과를 전달한다.

원래 보고서와 고정 source는 암호화 conversation record로 보존한다. CD의 수동·Save·Stage 경로와 GCR CLI의 Commit·Push 서비스 경로에 같은 보존 처리를 추가했다. 고정 source가 없는 예전 보고서는 현재 작업 파일로 대체하지 않는다. UI의 source 버튼은 host가 발급한 ID와 render revision만 전달하며 worker가 검증한 인용 위치의 저장된 source를 readonly 문서로 연다. 임의 경로나 command URI를 전달하지 않는다.

GCR CLI의 보존 구현은 `2f3bb73`이며 CLI `0.1.0-alpha.17`에 포함된다. CD는 공통 패키지 `0.1.0-alpha.23`과 CLI alpha.17의 tarball·manifest hash를 고정한다. 전역 CLI는 바꾸지 않는다. 이 변경은 client 기능이며 PRISM 서버 배포나 DB TLS 구성을 변경하지 않는다.

### C02 검증과 설치

확장 전체 회귀 166개, source/test typecheck와 build가 통과했다. 새 대화 검사는 고정 source·질문 재개·취소·설정 변경·webview ID/HTML 경계를 다룬다. 중앙 연결 검사는 실제 로컬 HTTPS publisher와 합성 모델로 같은 publication의 재동기화 후 재개 및 확인된 철회 후 미호출을 검증했다. PRISM의 실제 중앙 대화 검증으로 확대하지 않는다. 초기 회귀에서는 요약 화면 DOM mock의 selector 처리와 이전 package version 기대값이 실패했으며 수정 후 전체 166개가 통과했다.

실제 `gpt-6-astra / xhigh`의 첫 리뷰는 360초 제한에 도달해 실패했고 종료를 확인한 후 해당 fixture를 정리했다. 600초의 검증용 제한으로 별도 시작한 리뷰는 완료됐다. 실제 VS Code 1.137.0에서 Enter/Shift+Enter, 질문 checkpoint, 화면을 닫고 다시 연 뒤 답변·재개, source/base/caller 인용 4개를 확인했다. 작업 파일 변경 뒤에도 원래 source가 열렸다. 이후 source editor가 대화 탭을 가려 검증 도구가 다음 Send를 누르지 못했다. 이 관측 실패를 성공으로 바꾸거나 같은 리뷰를 재실행하지 않았다.

검증 도구에 대화 탭 복귀를 추가하고 최종 VSIX에서 같은 암호화 대화를 다시 열었다. 저장된 답변·인용과 source 이동을 확인하고 명시적 후속 질문 1개를 전송했다. 모델의 실제 source 조회 후 취소하여 cancelled·응답 없음과 native host exit 0을 확인했다. 첫 대화는 모델 호출 2회이며 패키지 재개 검사는 별도의 취소된 후속 실행 1회다. 검증용 profile의 암호화 기록·OS key와 fixture를 정리했다. 모델은 테스트 명령을 실행하지 않았다.

최종 VSIX SHA-256은 `9e4f75dcdec5bbd542e07828c0b20740c87d2e7c8202314e4584e1128cf2bba6`다. 포함된 bundle·CLI manifest가 빌드 결과와 일치한다. VS Code 1.90.2의 실제 Extension Host에서 활성화·command 24개·빈 이력 조회의 key 미생성을 통과했다. 사용자 VS Code의 기존 확장을 백업하고 이 VSIX를 설치했으며 설치 파일의 hash를 다시 대조했다. 열린 사용자 창의 reload는 강제하지 않았다. 공개 Marketplace 게시와 P08 전체 완료는 아직 아니다.

[패키지·검증·설치 증거](evidence/P08-CD-review-chat.json)를 따른다. 다음 범위는 P08-C03의 명시적 feedback 제출과 C04의 CLI/MCP 연결이다. P07 통합·복구와 P09–P13을 포함한 전체 goal은 계속 진행한다.


## P08-C05 — Commit Defender 제출 확인·대기열·로컬 후보

Commit Defender `2.4.0`의 source commit은 `221afd6`이며 공통 library alpha.25를 사용한다. 리뷰 요약·이력·명령 팔레트에서 제출 화면을 연다. 현재 worktree/profile의 저장된 보고서를 확인한 뒤 오탐·예외·새 판단 또는 최소 결과 metadata를 선택한다. 서버·tenant·repository·user·공개 범위와 실제 payload를 표시하며 확인한 hash만 보류하거나 전송한다. 원문 report/chat/source/local knowledge를 자동으로 포함하지 않는다.

보류는 암호화 outbox에만 저장하며 재개·새로고침·지식 동기화가 전송을 시작하지 않는다. 같은 entry를 다시 확인해 재전송하면 request ID를 유지한다. 서버 접수와 기준/예외 승인을 구분하고 접수 여부가 불명확한 실패를 성공으로 표시하지 않는다. 별도 사용자 선택으로 feedback message를 repository Local Memory candidate에 저장하며 자동 활성화하지 않는다. Workspace trust·설정·profile·선택 연결 변경 시 화면을 닫고 작업마다 report와 연결을 다시 검증한다.

전체 회귀 172개, source/test typecheck와 build가 통과했다. 제출 검사 6개는 실제 TLS fixture와 공유 queue로 확인한 hash·재전송·403/503·disconnect·보고서 소유권·snapshot·local candidate를 검증한다. VS Code 1.135.0의 source checkout과 최소 버전 1.90.2의 최종 VSIX에서 실제 command→연결 선택→미리보기→확인→보류→화면 재개→local candidate→전송→접수증→설정 변경 시 닫기를 검증했다. 합성 리뷰를 사용했으며 실제 모델 호출과 운영 서버 변경은 0회다. 두 native host의 종료와 task-owned OS credential·암호화 profile·fixture 정리를 확인했다. Native screenshot은 일부 잘린 이미지이며 전체 시각 검증 근거로 삼지 않는다.

VSIX SHA-256은 `6baec4e599408dc4bff6dec689591e8702135afc60834eb482575afb65cea3a0`다. 소스를 push하고 기존 2.3.0 설치본을 백업한 뒤 사용자 VS Code에 2.4.0을 설치했다. 설치된 실행 bundle·service manifest와 검증 VSIX의 hash가 일치한다. 사용자 창의 reload는 강제하지 않았다. Bundled CLI는 alpha.17을 유지하며 전역 CLI를 교체하지 않았다.

[제출 화면·검증·설치 증거](evidence/P08-CD-review-submission.json)를 따른다. 이번 전달은 C05의 client 부분이며 중앙 intake 검토·후보 전환·권한자 승인·승인 상태·새 bundle sync·실제 재리뷰 순환은 아직 남아 있다. 이 상태를 C05 전체 완료로 집계하지 않는다. P08-C04/C06과 이전 phase 잔여 조건, P09 출시 및 P10–P13을 포함한 전체 goal을 계속 유지한다.
