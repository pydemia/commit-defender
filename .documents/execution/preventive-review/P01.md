# P01: Commit Defender 선행 결함 보완

상태: 진행 중. P01-C01–C04의 입력·snapshot·결과 상태·출력 신뢰 경계를 구현하고 코드 회귀를 검증했다. Backend 분리와 실제 리뷰 화면 검증은 아직 남아 있다.

## P01-C01 — 리뷰 입력의 공통 수집 정책

Repository·directory·단일 파일·staged 리뷰·hook·commit message 생성에 같은 경로 정책을 적용했다. Credential 경로, `.commit-defender`/`.gcr`/`.codex*` 저장소, 생성물과 QA 출력, binary, Git ignore와 사용자 제외 패턴을 검사한다. Force-added tracked 파일도 ignore를 따른다. 일반 untracked source는 수집한다. 명시적인 `.commit-defender/<name>/SKILL.md`는 별도의 리뷰 자료 읽기 경로를 사용하며 ignore와 symlink 검사를 동일하게 받는다.

파일 내용은 경로 검사 후 읽는다. 파일·상위 디렉터리 symlink, index의 symlink/submodule mode, 저장소 밖 경로를 거부한다. 읽기 직전 재검사와 open 후 inode·realpath 검사를 추가했다. Rename의 이전 경로가 제외 대상이면 새 경로도 제외하며 Git pathspec처럼 보이는 파일명을 literal 경로로 처리한다. Ignore 조회 실패 시 무제한 수집으로 전환하지 않는다.

Report의 `source_exclusions`, summary의 Source coverage와 output log에 제외 경로·사유를 남긴다. Directory 제외는 하위 파일 개수로 부풀리지 않는다. Commit message는 staged 파일이 일부 제외되면 생성을 중단해 실제 commit 전체를 설명한 것처럼 표시하지 않는다.

2026-09-12 검증:

- `npm test`: 기존 provider 7개, source policy 10개 통과. Credential canary·nested ignore·일반 untracked·symlink 교체·rename·literal 파일명·private-only 요청·실제 hook bundle의 입력을 검사했다. Provider는 합성 CLI이며 실제 모델 성능 증거는 아니다.
- `npm run typecheck:test`, `npm run build`: 통과. 추적 중인 extension/hook bundle을 함께 갱신했다.
- Git의 `check-ignore`는 `--literal-pathspecs`를 지원하지 않았다. stdin 경로에 `./`를 붙이고 pathspec 환경을 정규화한 뒤 colon/glob 형태 파일명 회귀를 통과했다.

이 commit은 수집해 prompt로 전달하는 입력을 제한한다. Legacy 계정 CLI가 원래 cwd를 독립적으로 읽는 문제는 P02-C03/C05의 고정 source view·읽기 port 구현 범위이며 현재 읽기 격리를 보장한다고 주장하지 않는다. 실제 UI·VSIX 검증과 Marketplace 게시는 이 commit에서 수행하지 않았다.

## P01-C02 — 선택한 source로 diff와 marker 판정 고정

사용자 index 파일을 임시 index로 복사한 뒤 `write-tree`를 실행한다. HEAD·base tree와 index tree의 object ID를 고정하고 diff·삭제·rename·marker 내용은 해당 Git object에서 읽는다. 임시 index는 finally에서 정리하며 원래 index와 checkout을 쓰지 않는다. Conflict나 missing object가 있으면 working tree로 fallback하지 않고 리뷰 오류를 반환한다. SHA-1 상수 대신 해당 저장소 형식의 empty tree를 생성한다.

허용한 정확한 file entry로만 두 비교 tree를 만든다. Git의 literal pathspec도 파일이 디렉터리로 바뀌면 하위 경로를 포함할 수 있으므로 파일명 literal 처리만으로 수집 경계를 대신하지 않는다. 삭제된 파일은 base에서, 그 외 선택 파일은 index에서 marker를 읽는다. Related source 읽기도 같은 tree의 object를 사용하며 원래 working tree를 읽지 않는다. On-demand 리뷰는 첫 provider 호출 전에 선택한 저장 파일 내용을 보관한다. Report에는 staged base/source tree ID 또는 저장 파일별 content SHA-256을 남긴다.

## P01-C03 — 완료 상태와 hook 판정 분리

`review.status`에 `completed/partial/failed/cancelled`를 추가하고 파일별 `status`와 미수행 `not-run`, 중단 사유를 보관한다. `is_error`는 전체 실패를 나타내는 legacy 필드로 유지한다. 새 report의 완료 판단은 `status`를 사용하며 provider가 작성한 summary 문구로 상태를 추측하지 않는다. Completed는 수집 정책상 허용한 선택 입력의 완료이며 제외 coverage는 별도로 남긴다.

전체 provider 실패는 failed, 일부 실패·입력 또는 응답 잘림·API 완료 metadata 누락은 partial이다. 취소 시 앞서 완료한 finding을 보존하고 뒤의 파일은 미수행으로 남긴다. Timeout은 취소와 구분하며 완료한 파일이 없으면 failed, 있으면 partial이다. 미완료 결과에는 전체 품질 grade를 부여하지 않는다. 오류 메시지를 P3로 만들거나 새 report의 summary를 가짜 line finding으로 바꾸지 않는다.

API의 HTTP body 읽기까지 취소를 전달한다. 외부 AbortSignal과 자체 timeout을 함께 적용하고 body parse catch가 취소를 일반 네트워크 실패로 삼키지 않게 했다. 완전한 JSON이어도 유효한 review object가 아니면 실패이며 복구한 잘린 JSON은 partial이다.

Hook은 같은 Reviewer를 사용한다. 기존 정책은 완료/부분 결과의 P3 또는 모델 `blocking`을 차단하고 failed/cancelled는 차단하지 않는다. `resolveExitCode(report, 'advisory')`는 완료 상태·finding을 바꾸지 않고 차단 코드만 0으로 반환한다. 이 advisory 분기는 후속 backend/trigger 연결용이며 기존 사용자의 hook 설정을 전환하지 않았다.

Summary·상태 표시줄·history·finding panel에 완료 상태와 coverage를 반영했다. 취소나 파일 수 0이라는 이유로 새 report를 버리지 않으며 실패한 실행은 이전 진단을 교체한다. 재사용 summary panel의 Raw JSON이 최초 report에 묶여 있던 closure도 현재 표시 report를 읽도록 바꿨다.

## P01-C04 — 출력·경로·Repository Skill의 신뢰 경계

Finding의 file/line을 캡처한 source에 대조한다. 저장소 밖·미선택 경로와 범위 밖·소수·문자열 line은 거부하며 거부 개수와 `invalid-output`을 남겨 partial로 표시한다. 단일 파일 입력의 basename 별칭만 같은 파일로 해석하고 다른 경로를 현재 파일로 덮어쓰지 않는다. Report의 `source_anchors`는 content hash·line count·base/source 측을 보관한다. 이 anchor 검증은 모델이 실제 근거를 읽었다는 증명이 아니다.

댓글·Findings tooltip·Summary는 Markdown AST에서 HTML을 표시용 텍스트로 바꾸고 image를 불러오지 않는다. 일반 URL의 자동 링크도 같은 검사를 거친다. HTTP(S)와 검증된 source 링크만 확장이 발급한 불투명 ID로 처리하며 모델이 작성한 command/file/data/javascript URI를 실행하지 않는다. Native Markdown은 내부 `openReviewLink` command 하나만 허용한다. Summary의 메시지는 현재 render nonce·발급된 ID·정확한 message 필드를 검사하며 절대 경로나 줄 번호를 webview에서 받지 않는다. CSP로 외부 resource·임의 script를 막고 local resource root도 비웠다. Metadata를 escape하고 일반 강조·목록·코드 블록은 유지한다.

열려 있는 source 문서의 내용이 캡처 hash와 같으면 해당 문서로 이동한다. 파일이 바뀌거나 삭제됐거나 아직 열려 있지 않으면 캡처한 내용을 읽기 전용 문서로 연다. 경로 검사 후 별도의 filesystem open이 발생하는 경쟁을 피하기 위한 처리다. Source 내용은 최대 8 MiB 메모리 cache에 보관하고 평문 history 파일로 쓰지 않는다. Cache에서 사라진 staged source는 고정 Git blob과 hash로 복구하며 working-tree source는 현재 hash가 일치할 때만 복구한다. 복구할 수 없는 과거 source를 현재 파일로 대체하지 않는다. Inline comment·diagnostic·CodeLens는 현재 source와 줄·column이 유효할 때만 표시하고 문서 내용 변경 시 제거한다.

Repository Skill 본문은 system prompt에서 제거하고 untrusted user material로 전달한다. Skill은 provider·도구 설정·출력 schema를 바꾸지 못하며 32,000자 자료 한도를 넘으면 `context-truncated`로 partial을 남긴다. Markdown 표시 한도는 100,000자이며 생략 시 Raw JSON 안내를 표시한다. Legacy 계정 CLI가 원래 cwd를 독립적으로 읽는 제한은 여전히 P02-C03/C05에서 해결해야 한다. 이 commit을 전체 source 읽기 격리 완료로 계산하지 않는다.
