# P01: Commit Defender 선행 결함 보완

상태: 진행 중. P01-C01의 수집 정책을 구현·검증했다. P01 전체 완료 조건인 staged snapshot, 결과 상태, 출력 신뢰 경계, backend 분리와 실제 화면 검증은 아직 남아 있다.

## P01-C01 — 리뷰 입력의 공통 수집 정책

Repository·directory·단일 파일·staged 리뷰·hook·commit message 생성에 같은 경로 정책을 적용했다. Credential 경로, `.commit-defender`/`.gcr`/`.codex*` 저장소, 생성물과 QA 출력, binary, Git ignore와 사용자 제외 패턴을 검사한다. Force-added tracked 파일도 ignore를 따른다. 일반 untracked source는 수집한다. 명시적인 `.commit-defender/<name>/SKILL.md`는 별도의 리뷰 자료 읽기 경로를 사용하며 ignore와 symlink 검사를 동일하게 받는다.

파일 내용은 경로 검사 후 읽는다. 파일·상위 디렉터리 symlink, index의 symlink/submodule mode, 저장소 밖 경로를 거부한다. 읽기 직전 재검사와 open 후 inode·realpath 검사를 추가했다. Rename의 이전 경로가 제외 대상이면 새 경로도 제외하며 Git pathspec처럼 보이는 파일명을 literal 경로로 처리한다. Ignore 조회 실패 시 무제한 수집으로 전환하지 않는다.

Report의 `source_exclusions`, summary의 Source coverage와 output log에 제외 경로·사유를 남긴다. Directory 제외는 하위 파일 개수로 부풀리지 않는다. Commit message는 staged 파일이 일부 제외되면 생성을 중단해 실제 commit 전체를 설명한 것처럼 표시하지 않는다.

2026-09-12 검증:

- `npm test`: 기존 provider 7개, source policy 10개 통과. Credential canary·nested ignore·일반 untracked·symlink 교체·rename·literal 파일명·private-only 요청·실제 hook bundle의 입력을 검사했다. Provider는 합성 CLI이며 실제 모델 성능 증거는 아니다.
- `npm run typecheck:test`, `npm run build`: 통과. 추적 중인 extension/hook bundle을 함께 갱신했다.
- Git의 `check-ignore`는 `--literal-pathspecs`를 지원하지 않았다. stdin 경로에 `./`를 붙이고 pathspec 환경을 정규화한 뒤 colon/glob 형태 파일명 회귀를 통과했다.

이 commit은 수집해 prompt로 전달하는 입력을 제한한다. Legacy 계정 CLI가 원래 cwd를 독립적으로 읽는 문제는 P02-C03/C05의 고정 source view·읽기 port 구현 범위이며 현재 읽기 격리를 보장한다고 주장하지 않는다. 실제 UI·VSIX 검증과 Marketplace 게시는 이 commit에서 수행하지 않았다.
