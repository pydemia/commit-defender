## 재현 가능한 설치와 Extension Host

기존 extension에 package-lock이 없어 `npm ci`가 실패했다. `vscode-extension/package-lock.json`을 추가하고 ignore를 해제했다. 테스트 도구 `@vscode/test-electron`은 `3.1.0`, VS Code API 타입은 최소 지원 계열의 `1.90.0`으로 고정했다. Test runner의 개발 Node 요구는 `>=22`이며 extension/hook의 Node 18 bundle target과 구분한다.

`npm ci --no-fund --no-audit`, `npm run build`, `npm run typecheck:test`, `npm test`가 통과했다. Provider test는 실제 CLI를 흉내 낸 7개 검사이며 실제 모델 검증으로 계산하지 않는다.

`npm run test:extension`은 실제 VS Code를 별도 user-data/extensions 디렉터리와 임시 Git workspace로 실행한다. Activation, 선언된 command 18개 등록, clear/cancel, hook 기본 disable과 hook 미생성을 확인한다. 실제 개발자는 `.vscode/launch.template.json`을 로컬 `launch.json`으로 복사해 Development Host를 열 수 있다. Template은 `npm: build` task를 사용한다.

| 1.90.2                   | 20.9.0    | 29.4.0   | 통과 |

최소 버전은 `VSCODE_TEST_VERSION=1.90.2 npm run test:extension`, stable은 `VSCODE_TEST_VERSION=stable npm run test:extension`으로 실행한다. 설치된 앱은 `VSCODE_EXECUTABLE_PATH='/Applications/Visual Studio Code.app/Contents/MacOS/Code'`를 사용했다. 최초 `MacOS/Electron` 경로는 ENOENT였으며 Info.plist의 실제 executable `Code`를 확인한 뒤 재실행했다. 모든 성공 실행의 종료 코드는 0이다. 검증용 프로필과 workspace는 정리했고 사용자 VS Code 설정은 바꾸지 않았다.

## 현재 계정의 실제 Codex adapter

다음 명령은 명시적으로 최대 두 번의 실제 CLI 호출을 허용한다. 일반 `npm test`에서는 실행하지 않는다.

```sh
CD_CODEX_POC=1 \
CD_CODEX_EXECUTABLE=/Applications/ChatGPT.app/Contents/Resources/codex \
npm run test:executor-poc
```

기존 `callProvider`에 임시 wrapper를 전달해 Codex `0.153.4`, `gpt-6-astra`, `xhigh`, 현재 CODEX_HOME의 계정과 read-only 실행을 확인했다. `codex-work` 계정은 사용하지 않았으며 credential을 읽거나 복사하지 않았다. 허용 source는 임시로 작성한 `cache.py`·`caller.py` 두 파일뿐이다. 첫 호출의 120초 timeout과 전체 2회 상한을 설정했다.

두 파일에만 저장된 서로 다른 무작위 read-witness를 모델이 반환했고 부분 cache 때문에 `batch()`에서 ID `b`가 누락된다는 원인·호출 조건을 설명했다. 완료된 리뷰는 21,480ms, 두 번째 실제 CLI 실행의 취소는 1,509ms에 `AbortError`로 돌아왔다. 완료 리뷰 후 source 내용은 같았다. [실행 증거](./evidence/P00-executor-poc.json)에 source hash·판단과 제한을 저장했다. 취소 호출이 서버의 모델 실행 전 종료됐을 가능성은 구분한다.

P02-C05에서 해결할 한계가 있다. Legacy adapter의 `read-only`는 파일 쓰기 제한이며 source 읽기 allowlist를 보장하지 않는다. Witness는 두 파일을 읽었다는 증거이고 다른 파일을 읽지 않았다는 증거는 아니다. 불변 source view·읽기 port·도구 capability 제한과 비협조적인 자식 process 정리를 구현해야 한다. Legacy Codex adapter는 `maxTokens`를 CLI 한도로 전달하지 않으므로 이번 PoC의 실제 제한은 호출 수와 시간이다. 이 상태를 production snapshot isolation이나 token budget 검증 완료로 표시하지 않는다.

## 게시 사전 조건

`vsce show pydemia.commit-defender --json`은 exit 0으로 Marketplace version `2.3.0`을 반환했다. `vsce verify-pat pydemia`는 이번에도 20초 내 끝나지 않아 이 검사에서 시작한 process group만 종료했다. Credential 본문은 출력하지 않았고 publisher 쓰기 역할은 미확인이다. P09에서 최종 VSIX의 로컬 검증 뒤 본인 인증·쓰기 권한을 해결하고 같은 파일을 게시한다. 현재 Marketplace에 올린 변경은 없다.
