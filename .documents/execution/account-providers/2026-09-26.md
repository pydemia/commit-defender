## Antigravity live correction and additional allowance

First Antigravity invocation ended with CLI SUCCESS but was rejected by the adapter. Actual metadata: `init.agent` matches the private agent; `init.tools` reports the entire CLI tool catalog, not the selected agent's allowlist. Correct the allowlist to `finish` only and require the exact generated main agent plus only response/finalization event types. Retain strict terminal-state and JSON validation. Remove `--mode plan`, which has no effect when slash-command expansion is disabled.

## Scope and use

After applying the installed extension to a new/reloaded window, run **Commit Defender: Select Account Provider and Model**, choose Claude Code or Antigravity, then select its model (or CLI default) and reasoning effort. Set the corresponding User Setting `claudeCodePath` / `antigravityPath` if discovery fails. Claude Code requires safe mode; Antigravity requires the agent CLI, not the IDE launcher. Windows uses native `.exe` paths and the existing Job Object; new CLI adapters have not been actually run on Windows/Linux in this task.

Only explicit captured-source review, including review with pulled GCR context, is enabled here. The existing Codex restrictions in automatic service and review conversation are retained. Gemini API-key review remains available; legacy Gemini CLI configuration is preserved but removed from selectable account providers. No automatic token/profile migration is performed.

References: [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference), [Antigravity headless mode](https://antigravity.google/docs/cli/headless/), [Antigravity custom agents](https://antigravity.google/docs/subagents?tab=cli), [Gemini CLI migration](https://antigravity.google/docs/cli/gcli-migration).
