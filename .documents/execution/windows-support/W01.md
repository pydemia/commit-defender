# W01 — Windows 수동 리뷰 실행 기록

상태: W01 완료. Windows 11 ARM64의 실제 Extension Host에서
기존 Codex 계정의 Luna/high 리뷰 1건과 저장 결과 재조회에 성공했다.
W02–W04, 자동 service의 Windows 검증과 Marketplace 게시는 수행하지 않았다.

## 호출 전에 기록한 대상과 한도

GCR 계획 f5d0f41과 CD 인계 35b4874를 기준으로 진행한다.
실제 호출 대상은 기존 기본 Codex 계정의 gpt-5.6-luna / high다.
초기 한도는 결함 fixture 한 건, 240초다. 중앙 연결은 사용하지 않는다.

호출 전 fixture: CRLF sum.ts의 덧셈을 뺄셈으로 바꾸고 staged 상태로
고정한다. consumer.ts가 호출하며 [2,3] → 5 검사는 -5로 실패하고 빈
배열 → 0 검사는 통과해야 한다. .env 합성 canary는 제외한다.
completed 결함 지적, 암호화 이력 재조회 일치, 저장 결과 열기를 기대한다.

## 준비 실패와 재검증

첫 두 Host 준비 시도에서는 실제 모델 호출이 없었다. 첫 시도는 Node
시험 reporter가 기본 spec여서 실패 문구 검사 전에 중단됐다. TAP를
명시했다. 두 번째는 VS Code 1.137이 extensionTestsPath에서 저장소를
메모리 DB로 바꿔 fixture 신뢰 상태를 읽지 않아 중단됐다.
W01-preflight-trust.json의 modelCalls=0이 실제 호출 수다.

신뢰 검사를 끄지 않고 별도 startup 검증 확장을 사용한다. user-data-dir와
shared-data-dir 모두 임시 경로로 지정하고 생성 fixture만 신뢰 DB에
등록한다. 계정은 원래 Codex auth.json을 사용한다. 다시 시도할 대상은
동일 fixture이며 실제 호출 잔여 한도는 그대로 1회/240초다.

세 번째 준비 시도는 Workspace Trust를 통과했으나 Windows worker_threads의
대소문자 구분 환경에서 Path를 PATH로 읽지 못해 source 준비가 실패했다.
모델 호출은 0회다. Path/SystemRoot 조회를 대소문자 독립적으로 수정하고
실제 worker staged capture 회귀를 추가한다. 동일 fixture 1회/240초의
실제 호출 한도는 아직 사용하지 않았다.

단계 진단은 source 정리의 EPERM을 확인했다. Electron Node 24.18.1에서
읽기 전용 파일 rmSync 실패를 별도 재현했다. 생성한 private snapshot의
Git object 파일만 writable 속성으로 바꾼 뒤 삭제하도록 수정했다.
DACL이나 원본 저장소 속성은 바꾸지 않는다. 같은 Electron 런타임의
한국어/공백 경로 worker 캡처 회귀가 통과했다. 실제 호출은 여전히
0회이며 같은 fixture 1회/240초 한도를 적용한다.

P2 finding “Sum subtracts values instead of adding them”은 sum.ts 2행의
뺄셈 때문에 [2, 3]의 합이 -5가 되며 invoiceTotal 호출부의 기존 동작을
깨뜨린다고 지적했다. source/base/caller/test를 읽은 근거 8개가 남았다.
모델이 테스트를 실행했다고 주장하지 않는다. fixture 테스트의 실패와
빈 배열 테스트 통과는 모델 호출 전에 별도 Node 실행으로 확인했다.
민감 파일 제외용 `.env` 합성 canary는 결과에 없었다.

Host는 임시 user-data-dir/shared-data-dir와 생성 fixture만 신뢰한
저장소를 사용했다. Workspace Trust와 Electron sandbox를 해제하지
않았으며 검증 Host만 종료했다. 프로필·credential·fixture·session도
정리했다. 실제 호출 후 추가 모델 호출은 없었다.

전역 지침과 도구 격리는
[실제 CLI의 합성 catalog 검사](evidence/W01-codex-catalog.json)로
따로 확인했다. accountCalls=0, 외부 지침 canary 없음, review 도구 6개와
대화 도구 7개의 allowlist가 일치했다. provider의 의도적 HTTP 오류에
따른 exit 1은 catalog 관찰의 일부이며 리뷰 성공 결과가 아니다.

## 구현과 회귀

CD는 기존 provider/공통 리뷰 경로를 유지하며 native 저장 오류를
구분해 표시하도록 수정했다. Windows Credential Manager, NTFS
handle/DACL/reparse 검사, 고정 snapshot, shell 없는 프로세스 실행과
Job Object 후손 정리, auth.json만 연결한 per-process CODEX_HOME은
공통 client package에 들어 있다. 평문 저장 fallback은 없다.

- 최종 alpha.47: CD client 명세 22건 통과, build/typecheck와 test
  typecheck 통과. clean npm 설치와 VSIX 패키징도 완료했다.
- alpha.44 단계: 수동 리뷰 회귀 6건 통과. staged snapshot 고정,
  암호화 이력 재조회, 빈 profile의 무변경, 잘못된 설정/신뢰 거절,
  준비 취소와 worker 종료를 검사했다. 설정 회귀 4건도 통과했다.
- GCR alpha.46 집중 회귀: 47 통과, 0 실패, 플랫폼 전용 8 제외.
  이후 alpha.47의 read-only snapshot 정리 수정은 실제 Electron Node의
  한국어/공백 경로 worker 회귀 1건과 이번 실제 Host로 검증했다.
- 초기 광범위 GCR 검사와 CD 전체 suite를 전체 통과로 표시하지 않는다.
  GCR 초기 실행은 native 빌드/실행 중첩과 POSIX fixture 가정 때문에
  실패했다. CD는 필요한 수동 경로를 분리해 검증했다.

[회귀 수치](evidence/W01-regressions.json)와
[CD 검증 기록](evidence/W01-validation.json)에 실행 단계와 버전을 구분했다.
macOS/Linux 네이티브 회귀와 Windows x64는 실행하지 않았다.
staged/current-file은 기존 공통 경로를 사용하며 실제 모델 수용 검사는
staged 1회다. current-file에 대한 별도 실제 모델 호출은 하지 않았다.

## 수동 사용과 남은 제한

사용자가 편한 시점에 확장을 다시 활성화한 뒤 2.12.2 적용을 확인한다.
기존 Codex 계정과 명시적으로 선택한 provider/model을 유지하고 중앙
연결 없는 `standalone` 모드의 신뢰한 Git workspace에서 Command Palette의
`Commit Defender: Analyze Staged Files` 또는
`Commit Defender: Analyze Current File`을 실행한다. History에서 저장된
결과를 열 수 있고 `Commit Defender: Cancel Analysis`로 취소할 수 있다.
이번 작업에서 전역 모델·자동 실행 설정과 CLI는 변경하지 않았다.

검증된 조합은 Windows 11 ARM64, 로컬 고정 NTFS, VS Code 1.137,
Codex CLI 0.153.4와 파일 기반 기존 계정이다. auth.json hard link는
실행 임시 디렉터리와 같은 volume을 요구한다. Windows source index는
24 MiB 제한이며 helper 시작과 암호화 저장에 지연이 있다. x64,
Remote SSH/Container, UNC/network/FAT, keyring-only 계정과 자동 service는
이번 지원 판정에 포함하지 않는다. Windows directory fsync의 POSIX
동등 내구성도 주장하지 않는다. WSL 실행으로 대체한 검증은 없다.

[보존 확인](evidence/W01-preservation.json)에서 기존 설정 hash와 로그인,
Codex CLI 버전을 대조했다. 원래 auth.json의 hard link 수는 1로 복원됐다.
[다른 사용자 접근 시험](evidence/W01-other-user.json)은 승인된 임시 일반
계정으로 수행했고 읽기·쓰기·credential 조회를 거부했다. 계정과 프로필을
삭제했다. [정리 감사](evidence/W01-cleanup-audit.json)와
[정리 내역](evidence/W01-cleanup.json)에서 임시 credential/session/process
정리를 확인했다. 기존 사용자와 Codex Sandbox 계정은 보존했다.
