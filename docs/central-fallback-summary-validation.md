# 중앙 정책 fallback과 Summary 화면

## 기준 화면

연결 전 Summary는 `2cc3dde^`의
`vscode-extension/src/extension.ts`에 있던 화면을 기준으로 확인했다.
전체 요약, 파일별 검토, 코드 위치가 표시된 수정 제안 박스, 선택 파일
목록 순서와 기존 색상 토큰을 유지한다. 중앙 연결 뒤 추가된 실행·근거
정보와 제외 경로는 결과를 가리지 않도록 접힌 상세 영역에 둔다.

## 실행 동작

연결 선택에 `offlineBehavior`가 없으면 유효한 서명 캐시를 먼저 쓰고,
그마저 사용할 수 없을 때 로컬 지식으로 검토한다. 실행 중 중앙
스냅샷 확인이 실패해 코어가 `cancelled` 보고서를 만든 경우에도 사용자
취소 신호가 없고 중앙 접근 실패가 다시 확인되며 fallback이 허용되면
같은 소스 해시로 다시 준비한다.
재실행 보고서에는 중앙 선택과 로컬 실행, 전환 사유가 각각 기록된다.
명시적 `pause`·`cache-only` 선택과 중앙 스냅샷을 고정한 피드백 재검토는
자동으로 전환하지 않는다. 새 수동 리뷰 전에 소스가 바뀌면 재실행을
중단한다.
동일 입력의 저장된 리뷰는 `completed`일 때만 재사용한다. 실패하거나
취소된 결과와 불완전한 결과는 다음 실행에서 다시 검토한다.

상태 표시줄의 실행 중 클릭은 Output을 연다. 취소는 Commit Defender의
`Cancel Analysis` 명령으로 수행하며 Output에 사용자 취소를 기록한다.

## 검증

- 중앙 연결을 모델 실행 중 해제하는 fixture에서 두 번째 호출이 중앙
  정책 없이 같은 소스를 검토하고 완료 상태와 fallback 사유를 저장했다.
- 기존 중앙 연결·offline·권한 실패 테스트 13개를 OpenSSL 3으로 실행했다.
- 실패한 리뷰를 다시 실행하고 완료된 리뷰만 재사용하는 회귀 테스트를
  포함한 standalone 테스트 21개를 실행했다.
- `client-contract` 23개와 `review-security` 10개 테스트를 실행했다.
- 합성 보고서를 Chrome에서 렌더링해 요약, 파일별 검토, 수정 제안,
  접힌 상세 영역의 순서를 확인했다. 운영 저장소의 실제 모델 리뷰는
  수행하지 않았다.
